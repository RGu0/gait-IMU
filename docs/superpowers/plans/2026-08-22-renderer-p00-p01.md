# RAY-219 Renderer P-00/P-01 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the terminal renderer skeleton with the approved institutional login (P-00) and operator hub (P-01), driven by a deterministic mock adapter.

**Architecture:** `apps/terminal/renderer` is an isolated Vite React package. `TerminalApp` owns only view-local session state and invokes a `TerminalAdapter`; the supplied mock implements its fixed P-00/P-01 data and transitions. It neither imports device, filesystem, network, nor Python code, so replacement by RAY-248 IPC is limited to an adapter implementation.

**Tech Stack:** React 19, Vite, Vitest, Testing Library, existing `@gait/design-system` package.

**Spec:** `.project-context/documents/ui-design/UI布局设计_v0.5.md` sections 2, 3.2–3.5, 5 P-00/P-01, 11.1–11.3 and Appendix; Linear RAY-219 R1.

## Global Constraints

- P-00 is the cold-start surface; successful operator login enters P-01.
- No License, activation, self-registration, or password-reset UI; show the approved preconfigured-terminal copy.
- P-01 has exactly one filled primary action: `开始新的检测` when ready, otherwise `重新检查设备`.
- P-01 uses the 64px Hub AppBar, three fixed nav labels, icon+text+color statuses, three-channel left/right identity, and a five-row recent-record table.
- A disconnected module, battery below 30%, or missing factory calibration replaces the start action; upload backlog is a warning but does not block it.
- Renderer code does not import BLE, filesystem, upload/network clients, or business-decision modules; it consumes only the adapter snapshot.
- Use existing design-system tokens and primitives. Do not copy artboard inline styles or create a design-system fork.
